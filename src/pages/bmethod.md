## 科目Bの全体像

科目Bは150分で5問を解きます。問1の情報セキュリティは必須で、問2〜問11の10問から4問を選びます。1問20点、合計100点満点で、60点以上が合格の基準です。

| 時間の目安 | 内容 |
|---|---|
| 最初の5〜10分 | 選択する問題を決める（設問を中心に全体を見渡す） |
| 1問あたり約25〜27分 | 解答 |
| 最後の5〜10分 | 見直し、空欄の解消 |

## 問題の選び方

<div class="box point" markdown="1">

- 本文を全部読んでから選ぶ時間はありません。**設問を先に見て**、知識で答えられる空欄や計算がどれだけあるかで判断します
- 事前に「第一候補4問」と「予備2問」を決めておき、当日の難易度で入れ替えます
- 一度解き始めたら、よほどのことがない限り乗り換えないことです。乗り換えは時間の損失が大きくなります

</div>

## 解き方の型

### 1. 設問を先に読む

設問から「何を」「何字で」「どの観点から」答えるのかを把握してから本文を読みます。本文を読みながら、設問に関係する箇所に印を付けます。

### 2. 根拠は本文にある

科目Bの記述は、ほとんどの場合**本文の中に答えの根拠**があります。一般論を書くのではなく、本文の事例に即して答えます。

<div class="box caution" markdown="1">

「セキュリティを強化する」「適切に管理する」のような一般的な表現は、どの問題にも当てはまるため、ほぼ得点になりません。本文中の固有の名称や状況（例：「本社のプロキシを経由しない」「特権IDを共有している」）を使って具体的に書きます。

</div>

### 3. 設問の観点に合わせる

「〜の観点から」「〜に着目して」と指定されたら、必ずその観点で答えます。観点を外すと、内容が正しくても得点になりません。

### 4. 字数の8割以上を目安に

40字以内なら32〜40字を目安にします。短すぎると要素が不足し、長すぎると減点や、要点がぼやける原因になります。

## 文末の書き方

| 問われ方 | 文末の形 |
|---|---|
| 理由を述べよ | 「〜から。」「〜ため。」 |
| 目的を述べよ | 「〜するため。」 |
| 問題点を述べよ | 「〜できない。」「〜のおそれがある。」 |
| 対策・方法を述べよ | 「〜する。」 |
| 内容を述べよ | 名詞止めでもよい |

## 分野ごとの攻略のポイント

| 分野 | ポイント |
|---|---|
| 情報セキュリティ（必須） | 攻撃の名称と仕組み、対策の効果と限界を対で覚える。ログの読み取りが頻出 |
| 経営戦略 | SWOT、PPM、財務指標や損益分岐点の計算。計算問題は確実に取る |
| プログラミング | 擬似言語のトレースが中心。変数の値の表を作って追う |
| システムアーキテクチャ | 稼働率、性能、必要台数の計算。単一障害点の指摘 |
| ネットワーク | サブネット、DHCPリレー、VLAN、DNS、VPN。本文のネットワーク構成図を丁寧に読む |
| データベース | E-R図の多重度、SQLの空欄（外部結合、GROUP BY、HAVING、副問合せ）、排他制御 |
| 組込みシステム開発 | タスクの状態遷移、タイミング図、割込み処理。本文の仕様の数値を正確に追う |
| 情報システム開発 | UML、テスト設計、アジャイル。本文の要求と設計の対応を確認する |
| プロジェクトマネジメント | EVM、スケジュール、リスク対応。マネージャの立場での判断を問われる |
| サービスマネジメント | インシデント管理と問題管理の区別、SLA、可用性の計算、変更管理 |
| システム監査 | リスク → 監査要点 → 監査手続 → 監査証拠の流れ。本文の記述が直接の根拠になる |

## 本テキストの科目B演習の使い方

「基本」「標準」の演習は論点を絞った短い問題で、20分が目安です。「本番級」の演習は問題文の長さと設問数を本番に合わせてあり、25分で解き切ることを目標にしてください。紙は使わず、解答欄と画面上のメモだけで解く練習をしましょう。解答はテキスト欄に入力でき、このブラウザに自動保存されます。解き終えたら「解答例を表示」で、解答例と**採点のポイント**を確認し、自分の解答に必要な要素が含まれているかを自己採点します。
