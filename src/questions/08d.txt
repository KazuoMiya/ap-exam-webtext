Q: 関係データベースの表で、索引を作成しても、検索の高速化の効果が最も小さい列はどれか。
ア: 値が行ごとに異なる、会員番号の列
イ: 値の種類が二つしかない、有効か無効かを表す列
ウ: 検索の条件に頻繁に指定され、値の種類も多い、受注日の列
エ: 結合の条件に使われる、外部キーの列
正解: イ
解説: 値の種類が少ない列では、条件を指定しても行を少数に絞り込めないので、索引を使っても全件を読むのと変わりません。索引は、**絞り込みの効果が大きい列**に作成します。索引を増やすと、更新のたびに索引も更新するので、更新は遅くなります。

Q: 分散データベースに関するCAP定理の説明として、適切なものはどれか。
ア: 原子性、一貫性、独立性、耐久性の四つを満たせば、どのような分散処理もできる。
イ: 複製の数を増やすほど、一貫性と可用性の両方が高まる。
ウ: コミットの処理を、準備と確定の二つの段階に分けて行う。
エ: 一貫性、可用性、分断耐性の三つを、同時にすべて満たすことはできない。
正解: エ
解説: **CAP定理**は、一貫性（Consistency）、可用性（Availability）、分断耐性（Partition tolerance）のうち、同時に満たせるのは二つまでであるという定理です。ネットワークの分断は避けられないので、実際には、分断の間に一貫性と可用性のどちらを優先するかを選びます。

Q: 5行からなる表の列「評価」に、3行は数値が、2行はNULLが格納されている。この表に対する COUNT(*) と COUNT(評価) の結果の組合せはどれか。
ア: COUNT(*) は 3、COUNT(評価) は 3
イ: COUNT(*) は 5、COUNT(評価) は 5
ウ: COUNT(*) は 5、COUNT(評価) は 3
エ: COUNT(*) は 3、COUNT(評価) は 5
正解: ウ
解説: COUNT(*) は行の数を数えるので5、COUNT(列名) は、その列が**NULLでない行**だけを数えるので3です。SUM や AVG も、NULLを除いて計算します。AVG(評価) は、5ではなく3で割った値になります。

Q: 親の表の行を削除したときに、その行を参照している子の表の行も、同時に削除されるようにする参照動作の指定はどれか。
ア: ON DELETE CASCADE
イ: ON DELETE NO ACTION
ウ: ON DELETE SET DEFAULT
エ: ON DELETE SET NULL
正解: ア
解説: **CASCADE** は、親の行の削除や更新を、子の行にも連鎖させます。NO ACTION は、参照している子の行があれば削除をエラーにします。SET NULL は、子の行の外部キーをNULLにします。意図しない大量の削除を招くことがあるので、指定は慎重に行います。

Q: データベースの3層スキーマのうち、データベースに格納するデータの論理的な構造を、利用者やプログラムの見方、および物理的な格納の方法とは独立に定義するものはどれか。
ア: サブスキーマ
イ: 概念スキーマ
ウ: 内部スキーマ
エ: 外部スキーマ
正解: イ
解説: **概念スキーマ**は、関係データベースでは表の定義に当たります。外部スキーマは、利用者やプログラムから見た構造（ビューなど）、内部スキーマは、物理的な格納の方法（索引、ファイルの編成など）です。3層に分けることで、一つの層の変更がほかの層に及びにくくなります。

Q: データウェアハウスで用いられるスタースキーマの説明として、適切なものはどれか。
ア: すべての表を第3正規形まで正規化して、データの重複をなくし、更新時の異状を確実に防ぐ。
イ: 一つの表に、キーと値の組だけを格納する。
ウ: 節と辺を用いて、データ同士のつながりを表現する。
エ: 数値を持つファクト表を中心に、分析の切り口を表す複数のディメンション表を結び付ける。
正解: エ
解説: **スタースキーマ**は、中心のファクト表と、その周りの商品、店舗、日付などのディメンション表からなります。分析の問合せが単純になり、集計が速くなります。更新よりも参照を重視するので、あえて正規化を抑えます。
