---本文
X社は、日用品を販売する通信販売会社であり、会員向けのECサイトを運営している。会員はメールアドレスを利用者IDとし、パスワードでログインする。

### 〔ECサイトのログイン機能〕

- 同じ利用者IDで、パスワードを**5回連続**で誤るとアカウントを30分間ロックする。
- パスワードは、SHA-256 でハッシュ値を計算し、その値を会員テーブルに保存している。ソルトは使用していない。
- ログイン後は、配送先住所の変更や、登録済みのクレジットカードでの購入ができる。

### 〔不審なログインの発生〕

ある日、会員から「注文した覚えのない商品の発送通知メールが届いた」という問合せが複数寄せられた。情報システム部のY主任がログイン履歴を調べたところ、表1のような記録が多数見つかった。

表1　ログイン履歴（抜粋）

| 日時 | 送信元IPアドレス | 利用者ID | 結果 |
|---|---|---|---|
| 02:14:01 | 203.0.113.25 | a…@example.jp | 失敗 |
| 02:14:02 | 203.0.113.25 | k…@example.jp | 成功 |
| 02:14:04 | 203.0.113.25 | m…@example.jp | 失敗 |
| 02:14:05 | 198.51.100.7 | s…@example.jp | 失敗 |
| 02:14:06 | 198.51.100.7 | t…@example.jp | 成功 |
| （以下、約3万件の利用者IDに対して同様の記録が続く） | | | |

Y主任は、次のことを確認した。

- 少数の送信元IPアドレスから、**多数の異なる利用者ID**に対して、それぞれ1回ずつログインが試行されていた。
- ログインに成功した会員の多くは、他社のサービスで使っていたものと同じパスワードを、X社のECサイトでも使っていた。その他社のサービスでは、過去に利用者IDとパスワードが流出していた。
- ログインに成功したアカウントのうち一部では、配送先住所が攻撃者の指定した住所に変更され、登録済みのクレジットカードで商品が購入されていた。

### 〔対策の検討〕

Y主任は、上司のZ課長と相談して、次の対策を検討した。

1. ログイン時に、パスワードに加えて、会員のスマートフォンに送信する**ワンタイムパスワード**の入力を求める（多要素認証）。
2. 同じ送信元IPアドレスからの短時間での大量のログイン試行を検知し、遮断する。
3. 配送先住所の変更など、重要な操作の際に追加の確認を行う。
4. パスワードの保存方法を見直す。
---設問 1
（1）今回の攻撃の名称を答えよ。

（2）X社のECサイトにはアカウントロックの機能があるにもかかわらず、今回の攻撃を防げなかった理由を、表1と本文の内容に基づいて40字以内で述べよ。
---解答 1
（1）**パスワードリスト攻撃**

流出した利用者IDとパスワードの組を使い、パスワードを使い回している会員のアカウントへのログインを試みる攻撃です。総当たり攻撃と答えると誤りです。

（2）解答例：**各IDへの試行が1回ずつで、5回連続の失敗というロックの条件に達しないから。**

採点のポイント：「1つのIDに対する試行回数が少ない」ことと「ロックの条件（5回連続失敗）に達しない」ことの両方が書けているか。アカウントロックは**1つのIDへの連続した失敗**を数える仕組みなので、多数のIDに1回ずつ試す攻撃には効きません。
---設問 2
対策1について、ワンタイムパスワードを用いた多要素認証が今回の攻撃に有効である理由を、認証の要素の観点から40字以内で述べよ。
---解答 2
解答例：**流出したパスワード（知識）だけでは、所持する端末に届く値を入力できないから。**

採点のポイント：パスワードは「知識」、スマートフォンに届くワンタイムパスワードは「所持」の要素であり、**攻撃者は流出したパスワードしか持っていない**ことを示せているか。なお、ワンタイムパスワードを偽サイトでだまし取る中間者型のフィッシングには弱いため、より強固にするにはパスキー（FIDO2）の導入も検討に値します。
---設問 3
対策3について、配送先住所の変更の際に行う追加の確認として、具体的な方法を二つ挙げ、それぞれ30字以内で述べよ。
---解答 3
解答例（いずれか二つ）：

- **操作時にパスワードやワンタイムパスワードの再入力を求める。**
- **変更があったことを、登録済みのメールアドレスに通知する。**
- **新しい配送先への初回の発送前に、会員本人に確認の連絡をする。**

採点のポイント：ログイン済みの攻撃者でも突破しにくい**再認証**か、本人が不正に気づける**通知**になっているか。「パスワードを複雑にする」のように、ログイン後の操作の確認になっていない解答は題意に合いません。
---設問 4
対策4について、次の問いに答えよ。

（1）現在の保存方法で、会員テーブルが流出した場合に問題となる点を、ソルトを使っていないことに着目して40字以内で述べよ。

（2）保存方法の改善策を、40字以内で述べよ。
---解答 4
（1）解答例：**同じパスワードは同じハッシュ値になり、対応表から元のパスワードを推測されやすい。**

採点のポイント：ソルトがないと、ハッシュ値と平文の対応表（レインボーテーブル）が使えること、同じパスワードの会員がまとめて判明することのいずれかが書けているか。

（2）解答例：**会員ごとに異なるソルトを付加し、ストレッチングを施したハッシュ値を保存する。**

採点のポイント：「会員ごとに異なるソルト」と「ストレッチング（または bcrypt や Argon2 などのパスワード保存用の関数）」に触れているか。パスワードを**暗号化して保存する**という解答は、鍵が漏れると復元されるので不適切です。
