---本文
R社は、事務用品の卸売業を営んでいる。R社は、複数の倉庫の在庫を管理するシステム（以下、本システムという）のデータベースを設計している。

### 〔業務の概要〕

- 商品は、商品番号で一意に識別される。商品ごとに、発注点（在庫の合計がこの数量を下回ったら、仕入先に発注する数量）を定めている。
- 在庫は、商品と倉庫の組合せごとに、数量を管理する。ある倉庫に一度も入庫していない商品は、その倉庫の在庫の行が存在しない。
- 倉庫の間で、商品を移動することがある。

### 〔関係スキーマ〕

下線は主キーを表す。

- 商品（<u>商品番号</u>, 商品名, 発注点）
- 倉庫（<u>倉庫番号</u>, 倉庫名）
- 在庫（<u>商品番号</u>, <u>倉庫番号</u>, 数量）

### 〔発注の対象の商品の一覧〕

設計担当のS氏は、すべての倉庫の在庫の合計が、発注点を下回っている商品を求める、次のSQL文（以下、SQL1という）を作成した。

```sql
SELECT 商品.商品番号, SUM(在庫.数量) AS 合計
FROM 商品
  INNER JOIN 在庫 ON 商品.商品番号 = 在庫.商品番号
GROUP BY 商品.商品番号, 商品.発注点
  a   SUM(在庫.数量) < 商品.発注点
```

テスト用のデータは、表1と表2のとおりである。

表1　商品

| 商品番号 | 商品名 | 発注点 |
|---|---|---|
| P1 | ボールペン | 100 |
| P2 | ノート | 50 |
| P3 | 付箋 | 30 |
| P4 | ファイル | 40 |

表2　在庫

| 商品番号 | 倉庫番号 | 数量 |
|---|---|---|
| P1 | W1 | 60 |
| P1 | W2 | 30 |
| P2 | W1 | 40 |
| P2 | W2 | 20 |
| P3 | W1 | 10 |

S氏は、①SQL1の結果に、発注すべき商品が1件含まれていないことに気付き、SQL文を修正した。

### 〔出庫の処理〕

出庫の処理では、在庫の数量が、出庫する数量以上であることを確かめてから、数量を減らす必要がある。S氏は、次のSQL文（以下、SQL2という）を使うことにした。:商品、:倉庫、:数 は、プログラムから渡す値である。

```sql
UPDATE 在庫
SET 数量 = 数量 - :数
WHERE 商品番号 = :商品 AND 倉庫番号 = :倉庫 AND 数量 >= :数
```

プログラムは、②SQL2の実行によって更新された行の数を調べて、出庫ができたかどうかを判定する。

### 〔倉庫間の移動の処理〕

商品を、移動元の倉庫から移動先の倉庫へ移す処理は、一つのトランザクションの中で、次の順に行う。

1. 移動元の倉庫の在庫の数量を減らす。
2. 移動先の倉庫の在庫の数量を増やす。
3. コミットする。

テストで、③同じ商品について、倉庫W1から倉庫W2への移動と、倉庫W2から倉庫W1への移動を、ほぼ同時に実行したところ、一方の処理がエラーになった。
---設問 1
〔発注の対象の商品の一覧〕について、次の問いに答えよ。

（1）SQL1中の空欄 a に入れる適切な字句を答えよ。また、この条件を WHERE 句に書くことができない理由を、30字以内で述べよ。

（2）表1と表2のデータでSQL1を実行したとき、結果に含まれる商品番号と、その合計を、すべて答えよ。
---解答 1
（1）a：**HAVING**

理由の解答例：**WHERE 句は、集約の前の行に対する条件だから。**

（2）**P1（合計90）、P3（合計10）**

解説：WHERE 句は、グループにまとめる前の行を絞り込み、HAVING 句は、グループにまとめた後の結果を絞り込みます。集約関数の結果に対する条件は、HAVING 句に書きます。P1は 60 ＋ 30 ＝ 90 で発注点の100を下回り、P2は60で発注点の50以上、P3は10で発注点の30を下回ります。
---設問 2
本文中の下線①について、次の問いに答えよ。

（1）結果に含まれていない、発注すべき商品の商品番号を答えよ。また、含まれない理由を30字以内で述べよ。

（2）S氏は、結合の方法を変更し、SUM(在庫.数量) を、COALESCE(SUM(在庫.数量), 0) に書き換えた。変更後の結合の方法を答えよ。また、COALESCE が必要な理由を35字以内で述べよ。COALESCE(x, y) は、x がNULLでなければ x を、NULLであれば y を返す。
---解答 2
（1）**P4**　理由の解答例：**在庫の行がなく、内部結合では結果に現れないから。**

（2）結合：**LEFT OUTER JOIN**（左外部結合）

理由の解答例：**在庫の行がない商品は合計がNULLになり、比較が真にならないから。**

解説：在庫が全くない商品は、最も発注が必要な商品です。内部結合は、結合の相手がない行を結果から落とすので、「存在しないこと」を見つけたいときは、外部結合を使います。外部結合で補われた列はNULLになり、SUM の結果もNULLです。NULLとの比較は、真にも偽にもならない（不明になる）ので、HAVING 句の条件を満たしません。0に置き換えてから比較します。
---設問 3
〔出庫の処理〕について、次の問いに答えよ。

（1）下線②について、出庫ができなかったと判定するのは、更新された行の数が幾つのときか。

（2）表2の状態で、P2を倉庫W1から50個出庫する処理と、30個出庫する処理を、この順に実行した。それぞれの処理の結果と、実行後の倉庫W1のP2の数量を答えよ。

（3）数量を SELECT 文で読み取って確かめた後に、別の UPDATE 文で減らす方法と比べたとき、SQL2の方法の利点を、40字以内で述べよ。
---解答 3
（1）**0**

（2）50個の出庫：**できない**　30個の出庫：**できる**　実行後の数量：**10**

（3）解答例：**確認と更新が一つの文で行われ、その間にほかの処理が割り込めない。**

採点のポイント：読み取ってから更新する方法では、二つの処理が同時に同じ数量を読み取り、どちらも「足りる」と判断して、在庫がマイナスになることがあります。条件を付けた1文の UPDATE であれば、行のロックをとった状態で条件が評価されるので、この競合が起こりません。更新された行の数が0のときは、在庫の不足か、行が存在しないかのどちらかです。
---設問 4
〔倉庫間の移動の処理〕の下線③について、次の問いに答えよ。

（1）エラーの原因となった現象の名称を答えよ。また、その現象が起きた理由を、二つのトランザクションがロックを獲得する順序に着目して、50字以内で述べよ。

（2）この現象が起きないようにするための、処理の見直しの内容を、40字以内で述べよ。
---解答 4
（1）**デッドロック**

理由の解答例：**一方がW1、他方がW2の行をロックした後、互いに相手がロックした行を待ったから。**

（2）解答例：**移動の方向によらず、倉庫番号の小さい行から先に更新する。**

採点のポイント：デッドロックは、複数のトランザクションが、**異なる順序**で資源をロックするときに起こります。すべての処理で、ロックを獲得する順序を統一すれば、互いに待ち合う状態にはなりません。DBMSは、デッドロックを検出すると、一方のトランザクションをロールバックするので、プログラムの側では、その場合に処理をやり直す仕組みも用意します。
