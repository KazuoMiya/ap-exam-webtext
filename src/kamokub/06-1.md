---本文
Y社の人事部は、社内研修の申込みと受講を管理するデータベースを構築している。

### 〔データベースの設計〕

- 社員は複数の研修に申し込むことができ、1つの研修には複数の社員が申し込む。
- 研修ごとに定員がある。申込みは先着順に受け付け、定員に達した研修は申し込めない。

表の構造は次のとおりである。下線は主キーを、点線（ここでは＊）は外部キーを表す。

- 社員（<u>社員番号</u>, 氏名, ＊部署コード）
- 研修（<u>研修コード</u>, 研修名, 開催日, 定員）
- 受講（<u>＊研修コード</u>, <u>＊社員番号</u>, 申込日時）

### 〔空席のある研修の一覧〕

申込み画面には、空席のある研修とその残席数を表示する。次のSQL文を作成した。

```sql
SELECT 研修.研修コード, 研修.研修名,
       研修.定員 −   b   AS 残席数
FROM 研修   a   受講
  ON 研修.研修コード = 受講.研修コード
GROUP BY 研修.研修コード, 研修.研修名, 研修.定員
HAVING   b   ＜ 研修.定員
```

テスト用のデータは次のとおりである。

| 研修コード | 研修名 | 定員 |
|---|---|---|
| T01 | 情報セキュリティ基礎 | 3 |
| T02 | SQL入門 | 2 |
| T03 | リーダシップ研修 | 2 |

| 研修コード | 社員番号 |
|---|---|
| T01 | E001 |
| T01 | E002 |
| T02 | E001 |
| T02 | E003 |

### 〔申込みの登録処理〕

申込みの登録処理は、次の手順で行う。

1. 指定された研修の受講の行数を数え、定員に達していないことを確認する。
2. 受講に行を追加する。
3. コミットする。

テストで、T01 の残席が1のときに、2人の社員がほぼ同時に申し込んだところ、2人とも登録され、受講者が定員を超えてしまった。
---設問 1
社員と研修の関連について、次の問いに答えよ。

（1）社員と研修の間の関連の種類（1対1、1対多、多対多のいずれか）を答えよ。

（2）表「受講」がこの設計で果たしている役割を、30字以内で述べよ。
---解答 1
（1）**多対多**

（2）解答例：**多対多の関連を、二つの1対多の関連に分解する役割。**

採点のポイント：関係データベースでは多対多をそのまま表せないため、両方の主キーを組み合わせた**連関エンティティ**（受講）を置きます。社員と受講、研修と受講がそれぞれ1対多になります。
---設問 2
〔空席のある研修の一覧〕について、次の問いに答えよ。

（1）空欄 a に入れる結合の指定を答えよ。

（2）空欄 b に入れる字句を、COUNT関数を使って答えよ。

（3）空欄 a を INNER JOIN にした場合に、テスト用のデータで一覧に表示されなくなる研修の研修コードを答え、その理由を30字以内で述べよ。

（4）空欄 b を COUNT(*) にした場合に、T03 の残席数はいくつと表示されるか。また、その理由を40字以内で述べよ。
---解答 2
（1）**LEFT OUTER JOIN**

（2）**COUNT(受講.社員番号)**

（3）研修コード：**T03**　理由の解答例：**受講者が0人で、受講に結合する行が存在しないから。**

（4）残席数：**1**　理由の解答例：**外部結合で補われた受講側がNULLの行も、COUNT(*)では1件と数えるから。**

解説：正しいSQL文の結果は、T01（残席1）と T03（残席2）です。T02 は定員に達しているので HAVING で除かれます。COUNT(列名) は NULL を数えないため、申込みのない研修を0件と数えられます。外部結合と COUNT(*) の組合せは、試験でも実務でもよくある誤りです。
---設問 3
〔申込みの登録処理〕で、定員を超えて登録されてしまった原因と対策について、次の問いに答えよ。

（1）原因を、二つのトランザクションの処理の順序に着目して50字以内で述べよ。

（2）対策を一つ、50字以内で述べよ。
---解答 3
（1）解答例：**二つの処理がともに追加前の行数を数えて定員未満と判断し、その後それぞれが行を追加したから。**

（2）解答例（いずれか）：

- **手順1の前に研修の該当行を専有ロックし、確認から追加までを他の処理と同時に行わせない。**
- **研修に申込数の列を設け、「申込数＜定員」を条件とする更新が成功した場合だけ行を追加する。**

採点のポイント：（1）は「両方が確認を終えてから追加した」という**競合の順序**が書けているか。（2）は、確認と登録の間に他の処理が割り込めないようにする方法になっているか。SELECT … FOR UPDATE などで研修の行を専有ロックすると、後から来た処理は先の処理のコミットまで待たされ、正しい行数で判断できます。
