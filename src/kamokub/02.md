TITLE: ランレングス符号化のプログラム
FIELD: プログラミング
SLOT: 問3相当（選択）
LEVEL: 標準
TIME: 30
LEAD: 擬似言語で書かれた圧縮プログラムの空欄を埋め、トレースと弱点の分析を行います。
---本文
ランレングス符号化は、同じ文字の連続（ラン）を「文字」と「連続する個数」の組で表すデータ圧縮の方式である。たとえば文字列 AAABCC は A3B1C2 に変換される。

関数 encode は、英大文字だけからなる長さ1以上の文字列 s を受け取り、ランレングス符号化した文字列を返す。

### 〔プログラムで用いる記法〕

- s[i] は、文字列 s の i 番目の文字を表す。先頭の文字は1番目である。
- 文字列の長さは length(s) で求める。
- 文字列どうしの ＋ は連結を表す。toStr(n) は整数 n を10進数の文字列に変換する。
- 論理演算 and は、左側の式が偽の場合、右側の式を評価しない。

### 〔プログラム〕

```
○文字列型: encode(文字列型: s)
  文字列型: result ← ""
  整数型: n ← length(s)
  整数型: i ← 1
  整数型: cnt
  文字型: c
  while (i ≦ n)
    c ← s[i]
    cnt ← 1
    while ((  a  ) and (s[i ＋ cnt] が c と等しい))
      cnt ← cnt ＋ 1
    endwhile
    result ← result ＋ c ＋ toStr(  b  )
    i ←   c
  endwhile
  return result
```
---設問 1
プログラム中の空欄 a〜c に入れる適切な字句を答えよ。
---解答 1
- a：**i ＋ cnt ≦ n**
- b：**cnt**
- c：**i ＋ cnt**

採点のポイント：a は配列の範囲外を参照しないための条件で、and の左側に置くことで、範囲外のときは右側の s[i ＋ cnt] を評価しないようにしています。「i ＋ cnt ＜ n」とすると最後の文字との比較が行われず、末尾のランの個数を1つ少なく数えてしまいます。c では、読み終えたラン（cnt 文字分）の次の文字に進みます。
---設問 2
encode("WWWWBBW") を実行したときについて、次の問いに答えよ。

（1）関数の戻り値を答えよ。

（2）内側の while の中にある「cnt ← cnt ＋ 1」が実行される回数を答えよ。
---解答 2
（1）**W4B2W1**

（2）**4回**

解説：1つ目のラン W は4文字なので cnt は1から4へ3回増え、2つ目のラン B は2文字なので1回増え、最後の W は1文字なので増えません。3 ＋ 1 ＋ 0 ＝ 4回です。一般に、この回数は「入力の文字数 − ランの数」になります。
---設問 3
次の問いに答えよ。

（1）encode("ABCDE") の戻り値の文字数を答えよ。

（2）ランレングス符号化で、戻り値の文字数が元の文字列より長くなるのはどのような入力か。25字以内で述べよ。
---解答 3
（1）**10文字**（戻り値は A1B1C1D1E1）

（2）解答例：**同じ文字の連続がほとんどない文字列。**

採点のポイント：個数を必ず付けるため、長さ1のランは1文字が2文字になります。連続が少ないデータでは逆に膨らむことが、ランレングス符号化の弱点です。白黒の画像のように、同じ値が長く続くデータに向いています。
---設問 4
英大文字に加えて数字も含む文字列を encode で符号化すると、符号化した結果から元の文字列を一意に復元できなくなる場合がある。

（1）入力が "1112" のときの戻り値を答えよ。

（2）復元できなくなる理由を、（1）の結果を例にして40字以内で述べよ。

（3）この問題を解決する方法を一つ、40字以内で述べよ。
---解答 4
（1）**1321**

（2）解答例：**文字と個数の境目が分からず、1が321個とも、1が3個と2が1個とも読めるから。**

（3）解答例（いずれか）：

- **個数を常に2桁など固定の桁数で表し、文字と個数の境目を明確にする。**
- **個数の前に、入力に現れない区切り記号を入れる。**

採点のポイント：（2）は「文字と個数の区切りが判別できない」ことを、具体例で説明できているか。（3）は区切りを明確にする方法になっているか。固定桁にすると上限（2桁なら99）を超えるランを分割する処理も必要になります。
