## 補講：プロトコルの動作を手順で理解する

### 同じLAN内と、別のネットワークへの通信

端末は、宛先のIPアドレスと自分のサブネットマスクから、宛先が同じネットワークかどうかを判断します。

- **同じネットワーク**：ARPで宛先のMACアドレスを調べ、直接フレームを送る
- **別のネットワーク**：ARPで**デフォルトゲートウェイ**（ルータ）のMACアドレスを調べ、ルータにフレームを送る。IPパケットの宛先IPアドレスは最終の宛先のままで、宛先MACアドレスだけがルータのものになる

ルータを越えるたびに、**MACアドレスは付け替えられ、IPアドレスは変わりません**（NATを通る場合を除く）。ARPの要求はブロードキャストで送られ、ルータを越えません。

### ルーティングテーブルの読み方

宛先に一致する経路が複数あるときは、**ネットワーク部が最も長く一致する経路**（最長一致、ロンゲストマッチ）を選びます。どれにも一致しなければ、デフォルトルート（0.0.0.0/0）を使います。

| 宛先ネットワーク | ネクストホップ |
|---|---|
| 192.168.0.0/16 | R1 |
| 192.168.5.0/24 | R2 |
| 192.168.5.128/25 | R3 |
| 0.0.0.0/0 | R4 |

宛先が 192.168.5.130 のパケットは、上の三つすべてに一致しますが、最も長い /25 の経路が選ばれ、R3 に転送されます。

### DHCPの動作

1. DHCPDISCOVER：端末が、DHCPサーバを探す（ブロードキャスト）
2. DHCPOFFER：サーバが、貸し出すIPアドレスを提案する
3. DHCPREQUEST：端末が、提案されたアドレスの使用を要求する
4. DHCPACK：サーバが承認する

端末はまだIPアドレスを持たないので、要求はブロードキャストで送ります。DHCPサーバが別のネットワークにあるときは、ルータなどの**DHCPリレーエージェント**が中継します。

### DNSの仕組み

- **権威DNSサーバ**（コンテンツサーバ）：自分が管理するドメインの情報を保持し、問合せに答える
- **キャッシュDNSサーバ**（フルサービスリゾルバ）：端末からの問合せを受け、ルートサーバから順に権威DNSサーバをたどって（反復問合せ）答えを得る。結果を一定時間（**TTL**）保持し、同じ問合せにはキャッシュから答える
- 端末（スタブリゾルバ）からキャッシュDNSサーバへの問合せは、最終的な答えを求める**再帰問合せ**
- 権威DNSサーバの情報を複製して持つサーバをセカンダリサーバといい、複製の転送を**ゾーン転送**という
- 誰からの再帰問合せにも答えるキャッシュDNSサーバ（オープンリゾルバ）は、DDoS攻撃の踏み台にされるので、問合せ元を制限する

サーバを切り替える前にTTLを短くしておくと、古い情報がキャッシュに残る時間を短くできます。

### 電子メールの流れ

送信者のメールソフト →（SMTP、ポート587）→ 送信側メールサーバ →（DNSで宛先ドメインのMXレコードを検索し、SMTP、ポート25）→ 受信側メールサーバ →（POP3またはIMAP）→ 受信者のメールソフト。

### HTTPとWebの技術

- HTTPのメソッド：GET（取得）、POST（送信、作成）、PUT（更新）、DELETE（削除）
- ステータスコード：200番台は成功、300番台はリダイレクト、400番台はクライアント側の誤り（404は見つからない、403は禁止）、500番台はサーバ側の誤り（503は一時的に利用できない）
- **HTTP/2** は、一つのTCPコネクションの上で複数の要求と応答を並行して扱う。**HTTP/3** は、UDPの上で動く **QUIC** を使い、接続の確立を速くし、パケット損失の影響を小さくする
- **WebSocket**：一度確立した接続で、サーバとブラウザが双方向に通信する。チャットや通知に使う
- **REST**：資源をURLで表し、HTTPのメソッドで操作する設計の考え方。状態をサーバに持たない（ステートレス）
- **プロキシサーバ**は、クライアントの代わりに外部のサーバへ接続する。**リバースプロキシ**は、外部からの要求をサーバの代わりに受け付け、内部のサーバに振り分ける

### 負荷分散と冗長化

- **ロードバランサ**：IPアドレスとポート番号で振り分けるL4方式と、URLやCookieなどHTTPの内容で振り分けるL7方式がある。サーバの稼働を確認する**ヘルスチェック**で、故障したサーバを振り分け先から外す
- **VRRP**：複数のルータを1台の仮想ルータに見せる。端末は仮想IPアドレスをデフォルトゲートウェイに設定し、主となるルータが故障すると予備のルータが引き継ぐ
- **リンクアグリゲーション**：複数の回線を束ね、帯域の拡大と冗長化を行う

### 通信の品質

- **QoS**：音声や映像などの通信を優先して転送し、品質を確保する。優先制御と帯域制御がある
- 音声通話（VoIP）は、呼の制御に **SIP**、音声データの転送に **RTP**（UDP上）を使う。遅延、遅延のゆらぎ（ジッタ）、パケット損失が品質を左右する
- **MTU**：1回で送れるIPパケットの最大の大きさ。イーサネットでは1,500バイト。これを超えるパケットは分割（フラグメント化）される
- **輻輳制御**：TCPは、送信量を少しずつ増やし（スロースタート）、パケットの損失を検知すると送信量を減らす

### 障害の切り分けに使うコマンド

| コマンド | 確認できること |
|---|---|
| ping | 宛先までIPパケットが届くか、往復の時間 |
| traceroute（tracert） | 宛先までに経由するルータ。どこで止まっているか |
| nslookup、dig | DNSで名前解決ができるか |
| arp | IPアドレスとMACアドレスの対応 |
| ipconfig、ip | 自分のIPアドレスなどの設定 |

IPアドレスを指定した ping は通るのに、ホスト名では接続できないなら、DNSの名前解決を疑います。下位の層から順に確かめるのが切り分けの基本です。
