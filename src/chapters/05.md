## OSの役割

OS（オペレーティングシステム）は、ハードウェア資源を効率よく管理し、利用者やアプリケーションに使いやすい環境を提供します。主な機能はジョブ管理、タスク（プロセス）管理、記憶管理、入出力管理、ファイル管理です。

| 遷移 | きっかけ |
|---|---|
| 実行可能 → 実行 | ディスパッチャがCPUを割り当てる（**ディスパッチ**） |
| 実行 → 実行可能 | タイムスライスの終了、より優先度の高いタスクの割込み（プリエンプション） |
| 実行 → 待ち | 入出力要求など、CPU以外の資源を待つ |
| 待ち → 実行可能 | 入出力の完了など、待っていた事象の発生 |

<div class="box caution" markdown="1">

待ち状態から直接、実行状態に移ることはありません。待ちが解除されたタスクは、いったん実行可能状態の列に並びます。

</div>

### スケジューリング方式

| 方式 | 内容 |
|---|---|
| 到着順（FCFS） | 到着した順に実行する |
| ラウンドロビン | 一定のタイムクウォンタムごとに順番にCPUを割り当てる。時間を使い切ったタスクは列の末尾に戻る |
| 優先度順 | 優先度の高いタスクから実行する。低優先度のタスクがいつまでも実行されない飢餓状態に注意 |
| 処理時間順（SJF） | 処理時間の短いタスクから実行する。平均ターンアラウンドタイムが最小になる |

実行中のタスクを途中で中断して別のタスクに切り替えられる方式を**プリエンプティブ**、タスクが自らCPUを手放すまで切り替えない方式をノンプリエンプティブといいます。

## 排他制御とデッドロック

### セマフォ

共有資源を同時に使えるタスク数を制御する仕組みです。

- **P操作**：セマフォの値を1減らす。値が負になる（資源がない）ときはタスクを待ち状態にする
- **V操作**：セマフォの値を1増やす。待っているタスクがあれば実行可能にする

初期値を1にすると、同時に1つのタスクしか資源を使えない相互排除になります。

### デッドロック

複数のタスクが互いに相手の確保している資源を待ち、どれも進めなくなる状態です。次の4条件がすべてそろうと発生します。

1. 相互排除（資源を同時に1タスクしか使えない）
2. 保持と待機（資源を持ったまま別の資源を待つ）
3. 横取り不可（他のタスクの資源を奪えない）
4. 循環待ち（待ちの関係が輪になる）

<div class="box point" markdown="1">

最も実用的な予防策は、全タスクで**資源を確保する順番を統一する**ことです。これで循環待ちが起こらなくなります。

</div>

## 記憶管理

### 実記憶の管理

可変区画方式では、領域の確保と解放を繰り返すうちに小さな空き領域が散らばる**フラグメンテーション**（断片化）が起きます。使用中の領域を移動して空き領域を1か所に集めることを**コンパクション**といいます。また、プログラムが参照しなくなった領域を自動的に回収して再利用可能にする仕組みを**ガーベジコレクション**といいます。

### 仮想記憶

主記憶より大きなプログラムを実行できるように、補助記憶を主記憶の延長として使う仕組みです。プログラムを一定の大きさの**ページ**に分けて管理します。

- **ページテーブル**：論理ページ番号と物理ページ枠の対応表
- **ページフォールト**：参照したページが主記憶にない状態。ページイン（補助記憶から主記憶への読込み）が発生する
- **スラッシング**：主記憶が不足してページの入れ替えが頻発し、処理効率が極端に落ちる状態
- **TLB**：ページテーブルの一部を保持する高速なバッファ。アドレス変換を速くする

<div class="box example" markdown="1">

ページサイズが4Kバイト（16進数で 1000）、論理アドレスが 2A30 のとき、上位の 2 がページ番号、下位の A30 がページ内の位置です。ページテーブルで2番ページが5番のページ枠に対応していれば、物理アドレスは **5A30** です。

</div>

### ページ置換アルゴリズム

主記憶が満杯のときに追い出すページを決める方式です。

| 方式 | 追い出すページ |
|---|---|
| FIFO | 最も古く読み込まれたページ |
| LRU | 最後に参照されてから最も長い時間が経過したページ |
| LFU | 参照された回数が最も少ないページ |

参照列 1, 2, 3, 1, 4, 1, 2, 5 を3つのページ枠で処理すると、ページフォールトはLRUで6回、FIFOで7回です。LRUは直前に参照された1を残すため、5回目以降の動きが異なります。

## ファイルシステム

### パスの指定

- **絶対パス**：ルートディレクトリから目的のファイルまでの経路（例：/home/user/doc/a.txt）
- **相対パス**：カレントディレクトリから目的のファイルまでの経路。「..」は1つ上（親）のディレクトリ、「.」はカレントを表す

### バックアップの方式

| 方式 | 対象 | 復旧に必要なもの |
|---|---|---|
| フルバックアップ | すべてのデータ | 最新のフルバックアップだけ |
| 差分バックアップ | 前回のフルバックアップ以降に変更されたデータ | フルバックアップ ＋ **最新の差分**バックアップ |
| 増分バックアップ | 前回のバックアップ（種類を問わない）以降に変更されたデータ | フルバックアップ ＋ その後の**すべての増分**バックアップ |

差分は毎回の取得量が増えていきますが復旧が簡単で、増分は取得が速い代わりに復旧の手間が増えます。

## ミドルウェアと開発ツール

**ミドルウェア**は、OSとアプリケーションの中間で共通的な機能を提供するソフトウェアです。DBMS、Webサーバ、アプリケーションサーバ、トランザクションモニタ、メッセージキューなどがあります。

開発ツールには、統合開発環境（IDE）、デバッガ、バージョン管理システム、テスト自動化ツール、CI（継続的インテグレーション）ツールなどがあります。

## オープンソースソフトウェア（OSS）

OSSはソースコードが公開され、利用・改変・再配布が認められたソフトウェアです。無保証が原則で、ライセンス条件を守る必要があります。

| ライセンス | 特徴 |
|---|---|
| GPL | **コピーレフト**型。改変物を配布するときは、同じGPLでソースコードを公開する必要がある |
| LGPL | ライブラリとしてリンクして使うだけなら、利用側のソースコード公開は不要 |
| BSD、MIT、Apache | 非コピーレフト型。著作権表示などを残せば、改変物を独自のライセンスで配布できる |

<div class="box caution" markdown="1">

OSSは「著作権を放棄したソフトウェア」ではありません。著作権は作者が保持したまま、ライセンスで利用を許諾しています。社内で利用するだけなら、GPLでもソースコードを公開する義務はありません。

</div>
