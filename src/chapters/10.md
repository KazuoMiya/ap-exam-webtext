## 情報セキュリティの要素

JIS Q 27000 では、情報セキュリティを**機密性・完全性・可用性**（CIA）の維持と定義し、さらに真正性、責任追跡性、否認防止、信頼性を含めることがあるとしています。

| 要素 | 内容 | 対策の例 |
|---|---|---|
| 機密性 | 認可された者だけが情報にアクセスできる | アクセス制御、暗号化 |
| 完全性 | 情報が正確で、改ざんされていない | ハッシュ値の照合、ディジタル署名 |
| 可用性 | 必要なときに情報を利用できる | 冗長化、バックアップ |
| 真正性 | 利用者や情報が主張どおりのものである | 認証 |
| 責任追跡性 | 誰が何をしたかを追跡できる | ログの取得 |
| 否認防止 | 行為を後から否定できない | ディジタル署名 |

## 脅威と攻撃手法

### マルウェア

| 種類 | 特徴 |
|---|---|
| ウイルス | 他のプログラムに寄生して増殖する |
| ワーム | 単独で動作し、ネットワークを通じて自己増殖する |
| トロイの木馬 | 有用なソフトウェアを装って侵入し、不正な動作をする |
| ランサムウェア | データを暗号化したり窃取したりして、復旧や非公開と引き換えに金銭を要求する |
| ボット | 感染した端末を外部の指令（C&Cサーバ）で遠隔操作する |
| ルートキット | 侵入の痕跡を隠し、管理者権限を維持するためのツール群 |
| スパイウェア、キーロガー | 利用者の情報や入力を密かに収集して送信する |

### 人やメールを狙う攻撃

- **標的型攻撃**：特定の組織を狙い、業務を装ったメールでマルウェアを送り込む
- **ビジネスメール詐欺（BEC）**：取引先や経営者になりすまし、偽の口座へ送金させる
- **水飲み場型攻撃**：標的がよく閲覧するWebサイトを改ざんしてマルウェアを仕掛ける
- **フィッシング**：実在の組織を装った偽のサイトに誘導し、認証情報などを入力させる
- **ソーシャルエンジニアリング**：電話でのなりすまし、肩越しののぞき見（ショルダーハッキング）、ごみ箱あさり（トラッシング）など、技術を使わずに情報を盗む

### パスワードへの攻撃

| 攻撃 | 手口 |
|---|---|
| 総当たり攻撃（ブルートフォース） | 1つのIDに対して、文字の組合せを順にすべて試す |
| 辞書攻撃 | よく使われる単語やパスワードを試す |
| パスワードスプレー攻撃、逆総当たり攻撃 | よく使われるパスワードを1つ固定し、多数のIDに対して試す。ロックアウトを回避しやすい |
| パスワードリスト攻撃 | 他のサービスから流出したIDとパスワードの組を使ってログインを試みる。**パスワードの使い回し**が原因 |
| レインボーテーブル攻撃 | ハッシュ値と元のパスワードの対応表を事前に用意し、ハッシュ値から逆引きする |

ハッシュ値を保存する際に、利用者ごとに異なるランダムな値（**ソルト**）を加え、計算を何度も繰り返す（**ストレッチング**）と、レインボーテーブル攻撃が困難になります。

### Webアプリケーションへの攻撃

| 攻撃 | 内容 | 主な対策 |
|---|---|---|
| SQLインジェクション | 入力にSQL文の一部を混ぜて、データベースを不正に操作する | **プレースホルダ**（バインド機構）の使用 |
| クロスサイトスクリプティング（XSS） | 悪意あるスクリプトを脆弱なサイトに埋め込み、閲覧者のブラウザで実行させる | 出力時の**エスケープ**処理、Cookie の HttpOnly 属性 |
| クロスサイトリクエストフォージェリ（CSRF） | ログイン中の利用者に、意図しないリクエストを送信させる | 推測困難な**トークン**の埋込みと照合、SameSite属性 |
| OSコマンドインジェクション | 入力にOSのコマンドを混ぜて実行させる | シェルを起動する関数を使わない |
| ディレクトリトラバーサル | 「../」などでファイルパスを操作し、公開されていないファイルにアクセスする | ファイル名を直接受け取らない、パスの正規化 |
| セッションハイジャック | セッションIDを盗んで、正規の利用者になりすます | ログイン後にセッションIDを再発行、HTTPSの使用 |

### その他の攻撃

- **DoS／DDoS攻撃**：大量の通信でサービスを停止させる。DNSやNTPの応答を悪用して増幅させる**リフレクション攻撃**（DNSアンプ攻撃）もある
- **中間者攻撃（MITM）**：通信の間に入り込み、盗聴や改ざんを行う
- **DNSキャッシュポイズニング**：キャッシュDNSサーバに偽の情報を覚え込ませ、利用者を偽サイトへ誘導する。対策は DNSSEC、送信元ポート番号のランダム化
- **ゼロデイ攻撃**：修正プログラムが提供される前の脆弱性を突く
- **サプライチェーン攻撃**：取引先やソフトウェアの供給元など、セキュリティが手薄な関連組織を経由して侵入する
- **バッファオーバフロー**：確保した領域を超えるデータを送り込み、不正なコードを実行させる
- **プロンプトインジェクション**：生成AIへの入力や、AIが読み込む文書に悪意ある指示を紛れ込ませ、想定外の動作や情報漏えいを起こさせる

## 暗号技術

### 共通鍵暗号と公開鍵暗号

| 項目 | 共通鍵暗号 | 公開鍵暗号 |
|---|---|---|
| 鍵 | 暗号化と復号に同じ鍵 | 公開鍵と秘密鍵のペア |
| 代表例 | AES | RSA、楕円曲線暗号 |
| 速度 | 高速 | 低速 |
| 課題 | 鍵を安全に渡す**鍵配送問題** | 公開鍵が本人のものかの確認（PKIで解決） |
| n人が相互に通信するのに必要な鍵の数 | n(n − 1) ÷ 2 個 | 2n 個（各人がペアを1組） |

公開鍵暗号で秘密のデータを送るときは、**受信者の公開鍵**で暗号化し、受信者が自分の**秘密鍵**で復号します。

実際の通信では、データ本体を高速な共通鍵暗号で暗号化し、その共通鍵を公開鍵暗号で送る**ハイブリッド暗号**が使われます。TLSもこの方式です。

### ハッシュ関数

任意の長さのデータから固定長の値（ハッシュ値）を作る関数です。SHA-256 などがあります。

- **一方向性**：ハッシュ値から元のデータを求めることは事実上できない
- **衝突耐性**：同じハッシュ値になる異なるデータを見つけることは事実上できない
- 元のデータが1ビットでも変わると、ハッシュ値は大きく変わる

### ディジタル署名

<div class="box point" markdown="1">

1. 送信者は、本文のハッシュ値を**送信者の秘密鍵**で暗号化して署名を作り、本文と一緒に送る
2. 受信者は、署名を**送信者の公開鍵**で復号し、自分で計算した本文のハッシュ値と比較する
3. 一致すれば、**送信者本人が作成したこと**（真正性・否認防止）と**改ざんされていないこと**（完全性）を確認できる

共通鍵を使って改ざんを検知する仕組みは **MAC**（メッセージ認証コード）で、代表例が HMAC です。MACは完全性の確認はできますが、鍵を共有しているため否認防止はできません。

### PKI（公開鍵基盤）

- **認証局（CA）**：公開鍵とその所有者を結び付けた**ディジタル証明書**を発行し、自らの秘密鍵で署名する
- **CRL**（証明書失効リスト）：有効期限内に失効した証明書の一覧
- **OCSP**：証明書の失効状態をオンラインで問い合わせるプロトコル
- サーバ証明書は、通信相手のサーバが本物であることを利用者が確認するために使う

## 認証

### 認証の要素

| 要素 | 例 |
|---|---|
| 知識 | パスワード、PIN、秘密の質問 |
| 所持 | ICカード、スマートフォン、ハードウェアトークン |
| 生体 | 指紋、静脈、顔、虹彩 |

異なる要素を2つ以上組み合わせるのが**多要素認証**です。パスワードと秘密の質問の組合せは、どちらも知識なので多要素認証になりません。

生体認証では、本人を拒否する率（**本人拒否率 FRR**）と他人を受け入れる率（**他人受入率 FAR**）がトレードオフの関係にあります。判定を厳しくすると FAR は下がり、FRR は上がります。

### さまざまな認証方式

- **ワンタイムパスワード**：1回限りのパスワード。盗聴されても再利用できない
- **チャレンジレスポンス認証**：サーバが送る乱数（チャレンジ）とパスワードから計算した値を返す。パスワード自体は流れない
- **リスクベース認証**：普段と異なる環境（端末、場所、時間帯）からのアクセスのときだけ追加の認証を求める
- **パスキー（FIDO2）**：端末内の秘密鍵で署名して認証する。サーバにパスワードを保存しないので、フィッシングや流出に強い

### 認証・認可の連携

| 仕組み | 目的 |
|---|---|
| SSO（シングルサインオン） | 1回の認証で複数のシステムを利用できる |
| SAML | 異なるドメイン間で、認証結果（アサーション）をXMLでやり取りしてSSOを実現する |
| OAuth 2.0 | 利用者のパスワードを渡さずに、他のサービスへ**アクセス権限を委譲（認可）**する。アクセストークンを発行する |
| OpenID Connect | OAuth 2.0 を拡張し、**認証**の結果（IDトークン）を受け渡す |

## 情報セキュリティ管理

### ISMS

**ISMS**（情報セキュリティマネジメントシステム）の要求事項は JIS Q 27001 で、計画、運用、パフォーマンス評価、改善の流れで継続的に改善します（現在の規格本文は「PDCA」という語を明示していませんが、考え方は同じです）。管理策の詳細は JIS Q 27002 に示され、2022年版の国際規格では管理策が93項目、組織的・人的・物理的・技術的の4つに整理されました。

**情報セキュリティポリシー**は、基本方針、対策基準、実施手順の3層で構成されることが一般的です。

### リスクマネジメント

リスクアセスメントは **リスク特定 → リスク分析 → リスク評価** の順に進めます。

| リスク対応 | 内容 | 例 |
|---|---|---|
| リスク低減（軽減） | 対策により発生可能性や影響を下げる | ウイルス対策ソフトの導入 |
| リスク回避 | リスクの原因となる活動そのものをやめる | 個人情報を扱う業務を廃止する |
| リスク移転（共有） | リスクを他者と分担する | サイバー保険への加入、業務の外部委託 |
| リスク保有（受容） | 対策をとらず、リスクを受け入れる | 影響が小さいリスクを許容する |

### インシデント対応の体制

- **CSIRT**：インシデントの受付、分析、対応、関係者との調整を行う組織内のチーム
- **SOC**：ネットワークや機器を24時間監視し、攻撃を検知・分析する組織
- **ディジタルフォレンジックス**：不正アクセスなどの法的な証拠を保全し、調査・分析する技術

## 情報セキュリティ対策

### ネットワークの防御

| 対策 | 内容 |
|---|---|
| ファイアウォール | IPアドレスやポート番号に基づき、通過させる通信を制御する（パケットフィルタリング） |
| DMZ | 外部ネットワークと内部ネットワークの間に設けるセグメント。公開サーバを置く |
| WAF | Webアプリケーションへの通信の中身を検査し、SQLインジェクションやXSSなどの攻撃を遮断する |
| IDS | 不正な通信を**検知**して管理者に通知する |
| IPS | 不正な通信を検知して**遮断**する |
| UTM | ファイアウォール、IPS、ウイルス対策などを1台に統合した装置 |
| VPN | 通信を暗号化して、インターネット経由で拠点や在宅勤務者を安全に接続する |
| 検疫ネットワーク | 持込み端末のパッチ適用状況などを検査し、問題がなければ社内LANへの接続を許可する |

### 端末と運用の対策

- **EDR**：端末の挙動を監視し、侵入後の不審な動きを検知・調査・対処する
- **SIEM**：多数の機器のログを集めて相関分析し、攻撃の兆候を見つける
- **サンドボックス**：隔離した環境で不審なファイルを実行し、挙動を観察する
- **ゼロトラスト**：社内ネットワークも信頼せず、すべてのアクセスを都度検証する考え方。境界防御だけに頼らない
- **ペネトレーションテスト**：実際に攻撃を試みて侵入できるかを検証する

### 電子メールの対策

| 技術 | 内容 |
|---|---|
| SPF | 送信元ドメインのDNSに、正規の送信サーバのIPアドレスを登録し、受信側で照合する |
| DKIM | 送信側がメールにディジタル署名を付け、受信側がDNSで公開された公開鍵で検証する |
| DMARC | SPFやDKIMの検証に失敗したメールをどう扱うか（隔離、拒否など）の方針を送信側が宣言し、結果の報告も受けられる |
| S/MIME | メール本文の暗号化とディジタル署名を行う |
| OP25B | ISPが、動的IPアドレスから外部のメールサーバの25番ポートへの通信を遮断し、迷惑メールの送信を防ぐ |

### セキュリティの評価

- **CVSS**：脆弱性の深刻度を、基本評価基準などで0.0〜10.0の数値で評価する共通の基準
- **ISO/IEC 15408**：IT製品のセキュリティ機能を評価・認証する国際規格
- **JVN**：日本で使われているソフトウェアの脆弱性情報を公開するポータルサイト
