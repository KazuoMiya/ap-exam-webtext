## 補講：入力の設計、コード設計、帳票と画面の設計

### 入力データのチェック

| チェック | 内容 |
|---|---|
| フォーマットチェック | 桁数や形式（日付の形式、数字だけ、など）が正しいか |
| リミットチェック（レンジチェック） | 値が決められた範囲内にあるか |
| 論理チェック | 項目間の関係が矛盾していないか（開始日が終了日より前、など） |
| シーケンスチェック | データがキーの順に並んでいるか |
| 照合チェック | マスタファイルに存在するコードか |
| 重複チェック | 同じデータが二重に入力されていないか |
| チェックディジット | コードの各桁から計算した検査用の数字を末尾に付け、入力の誤りを検出する |

### コード設計

| コードの種類 | 内容 | 例 |
|---|---|---|
| 順番コード（シーケンスコード） | 発生した順に連番を付ける | 受注番号 0001、0002 |
| 区分コード（ブロックコード） | 範囲ごとに意味を持たせる | 100番台は営業部、200番台は開発部 |
| 桁別コード | 桁ごとに意味を持たせる | 上2桁が大分類、次の2桁が中分類 |
| 表意コード（ニモニックコード） | 略称など、意味が分かる文字を使う | TV-55-BK（55型の黒いテレビ） |

コードは、将来の件数の増加を見込んだ桁数にし、体系を途中で変えなくて済むように設計します。

### 画面と帳票の設計の要点

- 入力する順序を、入力元の伝票や業務の流れに合わせる
- 既定値、選択式の入力、入力候補の表示で、キー入力の量と誤りを減らす
- エラーは、どの項目がなぜ誤りで、どう直せばよいかを、その項目の近くに表示する
- 取消しややり直しができるようにし、重要な操作の前には確認を求める
- 同じ機能は、どの画面でも同じ位置、同じ表現にする（一貫性）
- 帳票は、関連する項目をまとめ、重要な情報を目立つ位置に置く

### Webデザインの用語

- **レスポンシブWebデザイン**：画面の幅に応じてレイアウトを自動で切り替え、PCとスマートフォンに同じページで対応する
- **パンくずリスト**：サイト内での現在の位置を、階層をたどる形で示す
- **CSS**：文書の構造（HTML）と見た目を分離し、デザインを一括して管理する
- **情報アーキテクチャ**：情報を分類し、利用者が目的の情報にたどり着きやすい構造を設計する

### マルチメディアの補足

- 1画素を24ビットで表すと約1,677万色（2<sup>24</sup>）、8ビットなら256色
- 解像度の単位 **dpi** は、1インチ当たりの点の数。600dpiで横2インチ、縦3インチの範囲を読み取ると、1,200 × 1,800 画素
- 動画の規格：H.264（MPEG-4 AVC）、その後継でより高い圧縮率のH.265（HEVC）
- **ストリーミング**：データを受信しながら再生する。全体のダウンロードを待たなくてよい
- 音声の規格：非圧縮のPCM、非可逆圧縮のMP3やAAC、可逆圧縮のFLAC
