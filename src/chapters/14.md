## システム監査とは

システム監査は、情報システムに関するリスクに対して、コントロール（管理の仕組み）が適切に整備・運用されているかを、独立した立場の監査人が点検・評価し、**保証**や**助言**を行う活動です。経済産業省の「システム監査基準」（令和5年改訂）は、システム監査がITガバナンスの実現に寄与することを目的としています。

評価の拠り所として、同じく経済産業省の「システム管理基準」があります。

### 保証型と助言型

| 種類 | 内容 |
|---|---|
| 保証型監査 | コントロールが適切であることを、監査人が一定の水準で保証する |
| 助言型監査 | コントロールの改善のために、問題点を指摘し改善策を助言する |

### システム監査人の要件

- **独立性**：監査対象から独立していること。**外観上の独立性**（組織や身分の上で、監査対象の部門に属さない）と**精神上の独立性**（公正で客観的な判断をする）の両方が求められる
- **専門的能力**：監査に必要な知識と技能をもつ
- **職業倫理と誠実性**、**正当な注意**：専門家として当然払うべき注意を払う

<div class="box caution" markdown="1">

システムの開発や運用を担当した人が、そのシステムを監査することはできません。外観上の独立性が損なわれるためです。

</div>

## システム監査の手順

1. **監査計画の策定**：監査の目的、範囲、時期、体制を決める。リスクの大きい領域を重点的に監査する（リスクアプローチ）
2. **予備調査**：資料の閲覧や聞取りで、監査対象の実態を把握し、本調査の監査手続を具体化する
3. **本調査**：監査手続を実施し、**監査証拠**を入手する
4. **評価と結論**：監査証拠に基づいて、コントロールの適切さを評価する
5. **監査報告**：監査報告書を作成し、**監査の依頼者**に提出する。指摘事項と改善提案（改善勧告）を記載する
6. **フォローアップ**：改善提案への対応状況を確認する

<div class="box point" markdown="1">

改善を**実施する責任は被監査部門**にあり、監査人は改善の実施状況を確認（フォローアップ）します。監査人が自ら改善を行うと独立性が損なわれます。

</div>

### 監査証拠と監査調書

監査の結論は、**十分かつ適切な監査証拠**に基づく必要があります。監査人が実施した手続、入手した証拠、結論に至った過程は**監査調書**に記録します。監査調書は、監査の結論を支える証拠資料になります。

## 監査技法

| 技法 | 内容 |
|---|---|
| チェックリスト法 | あらかじめ用意した質問項目に回答を求める |
| ドキュメントレビュー法 | 規程、設計書、記録などの文書を閲覧して確かめる |
| インタビュー法 | 関係者に直接質問する。回答の裏付けとなる証拠を別に確認する |
| 突合・照合法 | 関連する記録どうしを突き合わせて、一致するかを確かめる |
| 現地調査法 | 現場に出向いて、作業の状況や設備を観察する |
| CAAT（コンピュータ支援監査技法） | 監査人がコンピュータを使って、大量のデータを分析する |
| テストデータ法 | 監査人が用意したテストデータを処理させ、結果を予想と比べてプログラムの正しさを確かめる |
| ITF法 | 本番のシステムに監査用の架空口座を設け、本番の処理の中で監査用データを処理させて結果を確かめる |
| 監査モジュール法 | 監査用のモジュールを本番のプログラムに組み込み、条件に合うデータを抽出・記録する |
| ログ分析法 | システムのログを分析して、不正や異常な処理がないかを確かめる |

## 内部統制

### 内部統制の目的と基本的要素

金融商品取引法に基づく内部統制報告制度（いわゆるJ-SOX）の基準では、内部統制の目的と基本的要素を次のように整理しています。

| 4つの目的 | 6つの基本的要素 |
|---|---|
| 業務の有効性及び効率性 | 統制環境 |
| 報告の信頼性 | リスクの評価と対応 |
| 事業活動に関わる法令等の遵守 | 統制活動 |
| 資産の保全 | 情報と伝達 |
| | モニタリング |
| | ITへの対応 |

内部統制を整備・運用する責任は**経営者**にあります。

### 統制活動の例

- **職務分掌**：不正や誤りを防ぐため、承認、実行、記録などの職務を別の担当者に分ける。たとえば、発注を入力する担当者と、発注を承認する担当者を分ける
- **アクセス権限の管理**：業務に必要な最小限の権限だけを与え、定期的に棚卸しする
- **承認手続**、**照合**、**記録の保管**

### IT全般統制とIT業務処理統制

| 区分 | 内容 | 例 |
|---|---|---|
| IT全般統制 | 業務処理統制が有効に機能する**環境**を保証する、複数の業務システムに共通の統制 | システムの開発・保守の管理、運用管理、アクセス管理、外部委託先の管理 |
| IT業務処理統制 | 個々の業務システムで、承認された取引が正確に処理・記録されることを保証する統制 | 入力データのチェック、エラーデータの修正と再処理、マスタの維持管理 |

## ITガバナンス

ITガバナンスは、経営陣が組織のITの利活用を、経営目標の達成に向けて指揮し管理する仕組みです。JIS Q 38500 は、経営陣が行う活動として、ITの利用を**評価**（Evaluate）し、計画と方針を**指示**（Direct）し、成果と遵守状況を**モニタ**（Monitor）するモデル（EDM）を示しています。

情報セキュリティ監査、個人情報保護に関する監査なども、同様の枠組みで行われます。
