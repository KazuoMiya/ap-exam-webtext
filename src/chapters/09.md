## 階層モデルと通信機器

### OSI参照モデルとTCP/IP

| OSI | 主な役割 | TCP/IPの階層 | 代表的なプロトコル | 中継機器 |
|---|---|---|---|---|
| 第7層 アプリケーション層 | アプリケーション固有の処理 | アプリケーション層 | HTTP、SMTP、DNS、DHCP | ゲートウェイ |
| 第6層 プレゼンテーション層 | データの表現形式の変換 | 〃 | | 〃 |
| 第5層 セション層 | 通信の開始と終了の管理 | 〃 | | 〃 |
| 第4層 トランスポート層 | 端末間の信頼性の確保 | トランスポート層 | TCP、UDP | 〃 |
| 第3層 ネットワーク層 | 異なるネットワーク間の経路選択 | インターネット層 | IP、ICMP | ルータ、L3スイッチ |
| 第2層 データリンク層 | 隣接する機器間の伝送 | ネットワークインタフェース層 | イーサネット、PPP | スイッチ（ブリッジ） |
| 第1層 物理層 | 電気信号や光への変換 | 〃 | | リピータ、リピータハブ |

<div class="box point" markdown="1">

**スイッチ（L2スイッチ）** は MACアドレス、**ルータ** は IPアドレスを見て転送先を決めます。ARPは IPアドレスから MACアドレスを求めるプロトコルで、ネットワーク層とデータリンク層の橋渡しをします。

</div>

### LANの技術

- **イーサネット**：有線LANの標準。MACアドレス（48ビット）でフレームの宛先を表す
- **VLAN**：物理的な接続と関係なく、論理的にLANを分割する。スイッチ間では IEEE 802.1Q の**タグ**でVLANを識別する
- **スパニングツリープロトコル**：ループ状の接続で、フレームが回り続けるのを防ぐため、一部のポートを論理的に止める
- **リンクアグリゲーション**：複数の物理回線を束ねて1本の論理回線とし、帯域と冗長性を上げる
- **PoE**：LANケーブルで電力も供給する

### 無線LAN

IEEE 802.11 シリーズで規格化されています（802.11ax は Wi-Fi 6）。無線では衝突を検知しにくいため、送信前に一定時間待って衝突を避ける **CSMA/CA** を使います。ネットワーク名は **SSID**、暗号化方式は現在 **WPA3** が推奨です。

## IPアドレス

### IPv4アドレスとサブネット

IPv4アドレスは32ビットで、**ネットワーク部**と**ホスト部**に分かれます。どこまでがネットワーク部かを示すのが**サブネットマスク**で、「/24」のようにネットワーク部のビット数で表す方法を **CIDR** 表記といいます。

<div class="box formula" markdown="1">

- ネットワークアドレス ＝ IPアドレス AND サブネットマスク（ホスト部をすべて0）
- ブロードキャストアドレス：ホスト部をすべて1
- 割り当て可能なホスト数 ＝ **2<sup>ホスト部のビット数</sup> − 2**（ネットワークアドレスとブロードキャストアドレスを除く）

</div>

<div class="box example" markdown="1">

172.16.45.130/25 のとき、第4オクテットの130は2進数で 1000 0010。上位1ビットがネットワーク部なので、ネットワークアドレスは **172.16.45.128**、ブロードキャストアドレスは 172.16.45.255、ホスト数は 2<sup>7</sup> − 2 ＝ 126。

</div>

### プライベートアドレス

組織内で自由に使えるアドレスです。インターネットとの通信にはグローバルアドレスへの変換が必要です。

| 範囲 | CIDR |
|---|---|
| 10.0.0.0 〜 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 〜 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 〜 192.168.255.255 | 192.168.0.0/16 |

### 経路集約

連続した複数のネットワークを1つの経路情報にまとめることで、ルーティングテーブルを小さくできます。192.168.0.0/24 から 192.168.3.0/24 までの4つは、第3オクテットの上位6ビットが共通なので **192.168.0.0/22** にまとめられます。

### IPv6

アドレスは**128ビット**で、16ビットずつ8つに区切り、16進数をコロンで区切って表記します。連続する0のブロックは1か所だけ「::」で省略できます。アドレス空間が非常に広く、NATを使わずに機器ごとにグローバルアドレスを割り当てられます。

## ルーティング

- **静的ルーティング**：管理者が経路を手動で設定する
- **動的ルーティング**：ルータどうしが経路情報を交換して自動で更新する

| プロトコル | 方式 | 経路選択の基準 |
|---|---|---|
| RIP | 距離ベクトル型 | ホップ数（経由するルータの数）が最小 |
| OSPF | リンクステート型 | コスト（回線速度などから決める）の合計が最小 |
| BGP | パスベクトル型 | AS（自律システム）間の経路制御。インターネットの基幹 |

## トランスポート層

| 項目 | TCP | UDP |
|---|---|---|
| 接続 | コネクション型（3ウェイハンドシェイク） | コネクションレス型 |
| 信頼性 | 確認応答、再送、順序制御、フロー制御あり | なし |
| 速度 | オーバヘッドが大きい | 高速 |
| 主な用途 | Web、メール、ファイル転送 | DNSの問合せ、音声・動画のストリーミング、VoIP |

TCPの接続は **SYN → SYN/ACK → ACK** の3ウェイハンドシェイクで確立します。確認応答を待たずに送れるデータ量を**ウィンドウサイズ**といい、スループットの上限を決めます。

<div class="box formula" markdown="1">

TCPのスループットの上限 ≒ ウィンドウサイズ ÷ 往復遅延時間（RTT）

</div>

## アプリケーション層のプロトコル

| プロトコル | 役割 |
|---|---|
| DNS | ドメイン名とIPアドレスを対応付ける。Aレコード（IPv4アドレス）、AAAAレコード（IPv6）、MXレコード（メールサーバ）、CNAME（別名）、PTR（逆引き） |
| DHCP | 端末にIPアドレスやデフォルトゲートウェイなどを自動で割り当てる |
| SMTP | メールの送信と転送 |
| POP3 | メールサーバからメールを端末に取り出す |
| IMAP | メールをサーバ上に置いたまま管理する |
| NTP | 時刻を同期する |
| SNMP | ネットワーク機器の監視・管理。異常時はエージェントからマネージャへ**トラップ**を送る |
| ICMP | 通信の制御とエラー通知。ping や traceroute で使う |

### NATとNAPT

- **NAT**：プライベートアドレスとグローバルアドレスを1対1で変換する
- **NAPT**（IPマスカレード）：IPアドレスに加えて**ポート番号**も変換し、1つのグローバルアドレスを複数の端末で共有する

## 伝送時間の計算

<div class="box formula" markdown="1">

伝送時間 ＝ データ量（ビット）÷ {回線速度（ビット/秒）× 伝送効率}

</div>

<div class="box example" markdown="1">

30Mバイトのファイルを、伝送効率60％の100Mビット/秒の回線で送る。30 × 8 ＝ 240Mビット、実効速度は 100 × 0.6 ＝ 60Mビット/秒なので、240 ÷ 60 ＝ **4秒**。バイトとビットの換算（×8）を忘れないようにします。

</div>

## ネットワークの応用

- **VPN**：インターネットなどの公衆網上に、暗号化した仮想的な専用線を作る（IPsec-VPN、SSL-VPN など）
- **SDN**：ネットワーク機器の制御機能をソフトウェアに集約し、ネットワーク全体を一元的に制御する。制御部分とデータ転送部分を分離する
- **CDN**：コンテンツの複製を利用者の近くのサーバに配置し、配信を高速化する
- **5G**：高速大容量、超低遅延、多数同時接続を特徴とする移動通信システム
- **MQTT**：IoT向けの軽量なパブリッシュ／サブスクライブ型プロトコル
