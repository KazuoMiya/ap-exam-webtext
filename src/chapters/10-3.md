## 補講4：クラウド利用、監視、リスク対応の文書を整理する

### 監視と検知の仕組みの使い分け

名前の似た仕組みが多いので、「どこを見るか」「何をするか」で区別します。

| 仕組み | 見る場所 | 役割 |
|---|---|---|
| ファイアウォール | ネットワークの境界 | あて先、送信元、ポート番号で、通信を許可または遮断する |
| IDS／IPS | ネットワークやサーバ | 攻撃の特徴や異常な通信を検知する。IPSは遮断も行う |
| WAF | Webアプリケーションの手前 | HTTPの通信の内容を検査して、Webアプリケーションへの攻撃を遮断する |
| EDR | PCやサーバ（エンドポイント） | 動作を継続して記録し、侵入の後の不審な挙動の検知、調査、隔離を支援する |
| SIEM | 各機器から集めたログ | ログを集約して相関的に分析し、個々のログでは分からない攻撃の流れを見つける |
| DLP | データそのもの | 機密情報の特徴を基に、外部への送信や、外部の媒体への複製を検知して遮断する |
| SOC | 組織（体制） | 監視と分析を継続して行う専門の組織。検知した事象を、CSIRTに引き継ぐ |

<div class="box point" markdown="1">

「侵入を防ぐ」仕組み（ファイアウォール、WAF、ウイルス対策ソフト）と、「侵入を前提に、早く見つけて被害を抑える」仕組み（EDR、SIEM、SOC）を区別します。科目Bでは、「防御をすり抜けたマルウェアの活動を、どの仕組みのどのログで見つけるか」が問われます。ログを相関的に分析する前提として、すべての機器の時刻を、NTPで同期しておきます。

</div>

### クラウドサービスの利用と管理

| 用語 | 内容 |
|---|---|
| 責任共有モデル | 事業者と利用者が、それぞれの範囲の管理に責任を持つ考え方。IaaSではOSより上、SaaSでは利用者IDとデータの管理が、利用者の責任になる |
| シャドーIT | 組織が把握していない機器やクラウドサービスを、従業員が業務に使うこと。管理と監視が及ばない |
| CASB | 利用者とクラウドサービスの間で、利用状況の可視化と、方針に沿った利用の制御を行う仕組み。シャドーITの発見にも使う |
| SASE | ネットワークの機能と、セキュリティの機能を、クラウドの上でまとめて提供する考え方。拠点や自宅からの通信を、同じ方針で検査する |
| 設定の誤り | クラウドの事故の主な原因。ストレージの公開の設定、過大な権限、不要なポートの開放などを、定期的に点検する |

クラウドサービスの事業者の管理の状況は、利用者が直接監査することが難しいので、第三者の監査人による保証報告書や、ISMSクラウドセキュリティ認証などの取得の状況で確認します。業務を委託しても、委託元としての管理の責任は残ります。

### ソフトウェアの供給の経路を守る

| 対策 | 内容 |
|---|---|
| コード署名 | 配布元の真正性と、配布の後に改ざんされていないことを、利用者が検証できるようにする。脆弱性がないことの保証ではない |
| SBOM | ソフトウェアを構成する部品（ライブラリなど）の一覧。脆弱性が公表されたときに、影響を受ける製品を素早く特定できる |
| セキュアブート | 起動の過程で読み込むソフトウェアの署名を検証して、正当なものだけを実行する |
| 更新の検証 | 更新のファイルを、署名やハッシュ値で検証してから適用する |

開発に使うライブラリや、更新の配信の仕組みが侵害されると、正規の経路でマルウェアが配布されます（サプライチェーン攻撃）。署名に使う秘密鍵が盗まれると、マルウェアに正規の署名を付けられてしまうので、鍵は、耐タンパ性のある装置（HSM）などで厳重に管理します。

### リスク対応の結果を残す文書

ISMS（JIS Q 27001）では、リスクアセスメントからリスク対応までの結果を、文書として残します。

| 文書や用語 | 内容 |
|---|---|
| リスク受容基準 | どの大きさのリスクまでを受け入れるかを、あらかじめ定めた基準。経営者が承認する |
| リスク対応計画 | 選択した対応（低減、回避、移転、保有）を、誰が、いつまでに実施するかを定めた計画 |
| 残留リスク | 対応を実施した後に残るリスク。内容を明らかにして、リスク所有者が受容を承認する |
| 適用宣言書 | 必要な管理策と、採用した理由、実施の状況、および除外した管理策とその理由を記載した文書 |

<div class="box point" markdown="1">

リスクはゼロにはできません。対策の費用と効果を比べて、残ったリスクを「知ったうえで受け入れる」ことが、管理された状態です。知らないまま残っているリスクと、承認して保有しているリスクは、全く異なります。環境が変わればリスクも変わるので、残留リスクは、定期的に見直します。

</div>

### 攻撃の段階と対策の対応

標的型攻撃は、段階を踏んで進みます。どの段階で止めるかによって、対策が異なります。

| 段階 | 攻撃者の行動 | 主な対策 |
|---|---|---|
| 偵察 | 標的の組織や従業員の情報を集める | 公開する情報の見直し、従業員の教育 |
| 侵入（入口） | 攻撃メール、水飲み場型攻撃、脆弱性の悪用 | メールのフィルタ、修正プログラムの適用、多要素認証 |
| 拠点の確立 | マルウェアを常駐させ、外部の指令サーバと通信する | EDR、プロキシサーバでの通信の制限と記録 |
| 内部の探索と拡大 | 認証の情報を盗み、ほかのサーバへ侵入する | ネットワークの分割、特権IDの管理、認証のログの監視 |
| 目的の実行（出口） | 情報を外部へ送る、データを暗号化する | 出口の通信の監視、DLP、ネットワークから切り離したバックアップ |

一つの対策がすり抜けられても、次の段階で止められるように、対策を重ねます（多層防御）。
